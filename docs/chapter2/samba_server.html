2  Samba Server

2.1 Practical Objectives

  1. Students are able to install Samba Server.

  2. Students are able to modify Samba configuration to manage user access rights and shared resources.

  3. Students are able to practice file sharing between Ubuntu and Windows using Samba.

2.2 Theoretical Background of Samba Server

Samba is a free and open-source software that provides an implementation of the SMB/CIFS protocol for non-Windows operating systems such as Linux, Unix, and macOS [1]. A Samba server allows these operating systems to function as a file and print server in a Windows network environment, enabling Windows users to share and access files and printers from computers running non-Windows operating systems, as illustrated in Figure 2.1. Samba provides features such as authentication, authorization, encryption, and access rights management to ensure the security and privacy of shared data. It can also be integrated with directory services such as Active Directory to simplify user management in large network environments [2].

Samba operates using Server Message Block (SMB) protocol — a network protocol used to share files, printers, and other network resources between Windows or Unix computers [3]. SMB was originally developed by Microsoft as part of LAN Manager in the 1980s and has since become the de facto standard for file and printer sharing in Windows networks. SMB is a client-server protocol: the client sends requests to the server, and the server responds by delivering data or performing the requested operation, as illustrated in Figure 2.2. Data exchange is secured using encryption, authentication, and authorization.

Samba consists of two programs running in the background:

  • SMBD — the file server; spawns a new process for each active client.
  • NMBD — converts NetBIOS computer names to IP addresses and monitors shared resources on the network.

SMBD behavior is controlled through /etc/samba/smb.conf [4]. Samba can be configured as a file server, print server, or domain controller.

NoteUses of Samba Server
  • Share one or more directory trees across the network.
  • Centrally manage printers, print settings, and drivers for Windows clients.
  • Assist clients with network browsing.
  • Authenticate clients logging in to a Windows domain.
NoteAdvantages of Samba
  • Free and open-source — no licensing cost.
  • Available on multiple platforms for file sharing services.
  • Easy to configure and administer.
  • Connects directly to the network with minimal issues.
  • Highly reliable — errors are uncommon unless the server has hardware problems.
NoteKey Features of Samba
  1. User Authentication — Users must log in before accessing Samba services. Samba accounts are managed with smbpasswd.
  2. Write Access Control — Write permissions can be set per-share using read only or writable directives.
  3. Network Access Control — Access can be restricted by allowing or blocking specific IP addresses.

2.3 Samba Server Installation

ImportantBefore you begin

These steps assume Ubuntu Server is already installed and running. If not, complete the Ubuntu Server installation on Chapter 1.

  • 1. Installation
  • 2. Firewall Setup

Step 1 — Log in as root

Log in to your Ubuntu Server terminal as root (or prefix each command with sudo).

Step 2 — Update the package list

apt update

Step 3 — Install Samba

1apt install samba
1
An active internet connection is required — packages are downloaded during installation.

Continue the installation until complete.

Step 4 — Verify the installation

1systemctl status smbd
1
smbd is the main Samba file-server daemon. A status of active (running) confirms a successful install.

If successful, the output will show active (running), as shown in Figure 2.3.

If the status shows inactive (dead) (Figure 2.4), try starting Samba manually:

service smbd start

If it still does not start, reinstall Samba.

Step 5 — Check firewall status

ufw status

If the firewall is not active, enable it first:

ufw enable

Allow Samba traffic through the firewall

1ufw allow Samba
1
This opens UDP ports 137–138 and TCP ports 139 and 445, which Samba needs to communicate with Windows clients.
WarningDo not skip this step

Without allowing Samba through the firewall, Windows clients will not be able to connect to the shared folders.

2.4 Exercise

2.4.1 Setting Up File Sharing

Step 1 — Create the shared directories

1mkdir /home/share1
mkdir /home/share2
1
Both directories will be the root of each Samba share.

Create an empty test file inside each directory:

touch /home/share1/testfile1.txt
touch /home/share2/testfile2.txt

Step 2 — Set directory permissions

1chmod 777 /home/share1
chmod 777 /home/share2
1
777 grants read, write, and execute permission to all users. For production use, more restrictive permissions are recommended.

Step 3 — Create Samba users

1useradd user1
useradd user2
1
This creates a Linux system user. A separate Samba password is still required in the next step. Step 4 — Set Samba passwords 
1smbpasswd -a user1
1
The -a flag adds a new Samba user. Enter the password twice when prompted.

Repeat for user2:

smbpasswd -a user2

Step 5 — Configure access rights in smb.conf

Open the Samba configuration file:

nano /etc/samba/smb.conf

Scroll to the bottom and add the following blocks:

[share1]
1path = /home/share1
2valid users = user1, user2
3read list = user2
4write list = user1
browseable = yes

[share2]
path = /home/share2
valid users = user1, user2
read list = user1
write list = user2
browseable = yes
1
The directory on the server that will be shared.
2
Only these users may connect to this share.
3
user2 can only read files in share1.
4
user1 can read and write files in share1.

Save and exit by pressing Ctrl+X, then Y, then Enter.

Folder user1 user2
share1 Read + Write Read only
share2 Read only Read + Write

Step 6 — Restart Samba

1systemctl restart smbd
1
Configuration changes only take effect after a restart.

2.4.2 Testing File Sharing from Windows

Step 1 — Find the Ubuntu Server IP address

1ip a
1
Look for the IP address on the enp0s8 adapter (the host-only adapter configured earlier).

Note the IP address (e.g., 192.168.56.101).

Step 2 — Open the shares in File Explorer

On your Windows machine, open File Explorer and type the following in the address bar:

\\192.168.56.101

Confirm that both share1 and share2 are visible, as shown in Figure 2.5.

Step 3 — Test access as user1

Click share1 and log in as user1 when prompted. Check each of the following:

  • Can you view the contents of share1?
  • Can you create a new file inside share1?
  • Can you copy a file from share1 to local Windows storage?

Then navigate to share2 (still logged in as user1) and repeat the same checks.

TipExpected result for user1
  • share1 → can view, create, and copy files ✓
  • share2 → can view and copy files, but cannot create or modify files ✗

Step 4 — Disconnect and switch to user2

Open Command Prompt on Windows and check the active connection:

net use

Disconnect it (replace \\name with the connection name shown above):

1net use \\name /delete
1
Disconnecting is necessary — Windows caches credentials, so the old session must be cleared before logging in as a different user.

Step 5 — Test access as user2

Connect again to \\192.168.56.101, log in as user2, and check both share1 and share2.

TipExpected result for user2
  • share1 → can view and copy files, but cannot create or modify files ✗
  • share2 → can view, create, and copy files ✓
